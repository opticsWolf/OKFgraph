01 · Positioning

Files are the truth.
The graph is the index.

Most knowledge systems swallow your documents into a database you can never cleanly leave. OKFgraph inverts that: the bundle — a directory of Markdown with frontmatter, wikilinks, and content-hash assets — is the source of truth. The database is a derived, disposable index: delete it, re-import, get the same graph back.

BundleMarkdown + frontmatter + [[links]]
→
importlint · chunk · embed · link
→
ladybug indexgraph + vectors + FTS, one file
→
search / exportanswer, or Markdown back out

For humans

Edit in any editor, sync with git, open the same folder in Obsidian. No export step stands between you and your knowledge — it was files all along.

For agents

Five MCP tools — search, read, traverse, ingest, export_bundle — with deterministic output. Same answer for the same query, every run, so evals stay meaningful.

For pipelines

Delta-aware import re-embeds only changed files. diff and doctor give CI exit codes. produce turns a SQLite database into a linted bundle with observation notes.

02 · Core features

Everything a knowledge base needs.
Nothing it doesn't.

Hybrid search

Dense Jina v5 vectors fused with full-text search by RRF — at concept and chunk granularity. Matryoshka truncation (default 512 dims) keeps the index lean without re-embedding.

Model-free PPR

Lexical seeds → exact Personalized PageRank over the link graph. Topic search with no embedding model loaded — cold sessions answer in milliseconds.

Delta-aware import

File hashes decide what changed; only changed files re-embed. --purge drops deleted concepts (with tombstones and soft-delete safety).

Doctor & diff

A 0–100 health score (broken links, orphans, stale, duplicates) with safe --fix; structural diff for drift between graph and folder. Both CI-ready.

Obsidian interop

Wikilinks resolve by uid → aliases → title → stem; ambiguous names never resolve. Export --flavor obsidian round-trips edge-losslessly.

Image awareness

Caption route for cheap text graphs; ONNX vision route (Jina omni-nano, paired with text-nano) embeds actual image content. Content-hash dedup, okf-asset:// links.

Thoughts as knowledge

Persist session reasoning directly — ingest_thoughts(text, topic). Namespaced IDs (thoughts/<topic>/<ts>_<id>) export into a tidy tree. File-free mode runs a whole graph with no bundle directory.

Produce from data

okf produce --from sqlite renders any database as a bundle — one concept per table, FKs as links — with auto-generated ## Observations (empty tables, NULL/dup rates, orphan FKs) and a log.md changelog.

03 · Retrieval

Three gears, one deterministic engine.

Every query runs the same pipeline in the same order. No sampling, no re-ranking lottery — golden fixtures pin PPR scores, diff reports, and doctor scores byte-stable.

GearWhenModel loadHow
rank=none defaultOpen questionsOnce per sessionVector + FTS, RRF-fused
rank=hubAuthority mattersOnce per sessionRRF blend with hub (link-authority) scores
rank=pprCold / topic searchNoneLexical seeds → exact Personalized PageRank

Elegant by Subtraction

The ranking core is pure functions over sorted inputs: fixed PPR constants, fixed accumulation order, last-token pooling (as Jina v5 requires), L2-normalised Matryoshka vectors. The same query returns the same ranking on any machine — the property that makes agent evals and regression tests possible.

okf search "table OCR routing" --rank ppr
# → concepts, no ONNX session, ~ms

okf search "table OCR routing" --target chunks
# → exact passages, expandable to context

okf read slanet --include context --max-tokens 1500
# → self first, then PPR-ranked neighbours

MCP for agents, CLI for humans and CI, Python for pipelines — all three drive the same OKFRouter facade. Maintenance (diff, doctor, import) stays CLI-only, keeping the agent tool surface at five.

  --thoughts "..." --topic auth

Python · pipelines

r = OKFRouter(bundle_root="./kb",
              db_path="kb.db")

Thin facade over injected components. File-free: OKFRouter(db_path=...) alone.

05 · Ingestion engine

bobine 0.5.13

Standalone PDF / Office / text → Markdown engine — pure-Rust core, Python bindings. OKFgraph calls it for everything that isn't already Markdown, behind a swappable DocumentConverter seam. No torch, no optimum, no opencv — not even on the Python side.

Routed pages

Every page takes exactly the pass it needs: never (born-digital text, milliseconds), surgical (formulas only), always (full structure for scans).

Formula OCR

TexTeller ONNX decodes math regions to LaTeX — int8 default (~319 MB), ~5× faster per crop than the legacy backend it replaced.

Layout + tables

DocLayout-YOLO structure, PaddleOCR lines in reading order, SLANet-plus table structure — CPU-pinned by measurement, not superstition (see below).

Office, fully

docx/xlsx/pptx plus legacy doc/xls/ppt. Excel yields per-sheet CSV and typed JSON alongside Markdown; embedded pictures stage to content-hash assets.

06 · Embedding runtime

embroider 0.3.1

Jina v5 text + image embeddings over ONNX Runtime — Rust core, PyO3. The shared session-policy library both OKFgraph and bobine build on: one pinned runtime, per-slot CPU/CUDA routing, golden-vector conformance. Inference stays consumer-side; embroider owns sessions and policy.

One runtime

SessionPolicy::ort_defaults() binds a single onnxruntime==1.29.0 dylib — CPU or CUDA, never both, chosen by install extra, never by luck.

Devices × precision

cpu XOR cuda; fp32 on CPU, fp16 on CUDA. fp16-on-CPU is a hard error, not a silent stall. Per-model provider lists encode what the benches proved.

Frozen contract

Smart-resize vision contract, last-token pooling, L2-norm, Matryoshka ladder. Checked-in golden vectors fail the build on drift — alignment with stored indexes is structural.

Fail-closed acquisition

Models fetch from pinned revisions into a versioned cache; a Meta (dimension/contract) mismatch aborts before a single vector is written. A mid-run space switch can never poison an index.
