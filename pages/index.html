Your notes are the database.

OKFgraph is a file-first knowledge graph. Your knowledge lives as plain Markdown files — readable in any editor, versioned in git, openable in Obsidian — while a ladybug index serves it back with hybrid semantic search over locally-run Jina v5 embeddings. There is no server to operate, no torch anywhere in the stack, and no export step standing between you and your data: it was files all along, the database is just a disposable, rebuildable view over them.

01 · Positioning

Files are the truth.
The graph is the index.

Most knowledge systems swallow your documents into a database you can never cleanly leave: the files go in, vectors and edges come out, and the originals rot or vanish. Migration becomes a project, auditing becomes archaeology, and the moment the vendor changes direction, your corpus is hostage. OKFgraph inverts the relationship. The bundle — a directory of Markdown files with frontmatter metadata, [[wikilinks]], and content-hash image assets — is the source of truth, and it stays that way forever. The database is a derived index: delete it, re-import the same folder, and you get the same graph back, deterministically.

This inversion shapes every workflow the system supports. Because files are canonical, editing knowledge means editing text — in any editor, through any review process, with full git history — and re-importing only what changed. Because the index is disposable, there is no backup strategy to design and no schema migration to fear: the index is rebuilt, never migrated. And because agents speak to the graph through five stable, deterministic tools, the same question returns the same answer on every run, which is what makes evaluation and regression testing of knowledge workflows possible at all.

For humans

Knowledge work stays in tools you already trust. Write notes in your editor of choice, review them as pull requests, sync them with git, and open the very same folder in Obsidian when you want a visual graph. Curation — fixing a link, clarifying a paragraph, merging two duplicates — is just editing text, and the next import picks it up. There is no admin console to learn and no proprietary format silently holding your thinking hostage.

For agents

Coding agents need memory they can read and write without ceremony. Five MCP tools — search, read, traverse, ingest, export_bundle — cover the whole lifecycle, and every one of them returns deterministic output: sorted traversal order, fixed ranking constants, pinned fixtures. Persist session reasoning with ingest_thoughts, recall it weeks later with search, and trust that an eval written today still means the same thing next quarter.

For pipelines

Production knowledge bases are built, not written. Delta-aware import re-embeds only changed files, so nightly re-indexing of a ten-thousand-file corpus costs minutes, not hours. diff and doctor return CI exit codes, so a docs PR can gate on graph health the same way code PRs gate on tests. And produce turns a SQLite database into a linted, observation-annotated bundle — structured data in, curated knowledge out.

02 · Workflow

A day with OKFgraph,
start to finish.

What follows is the complete loop — from an empty folder to a queried, maintained, exported knowledge base — exactly as you would run it. Each step shows the command, what it does, and what happens underneath, so there is never any mystery about where your words go.

Step 1

Plant the bundle

A bundle is just a folder of Markdown files with a little frontmatter: a title, some tags, a stable id, and [[wikilinks]] to other notes. You create it with any editor — there is no special authoring tool, because the format is the tool. One command records where the bundle lives and where its index will go, so every later command picks up the same paths from okfgraph.toml without flags.

okf init --db kb.db --bundle kb/
# kb/auth.md:
# ---
# title: Session auth
# tags: [auth, sessions]
# ---
# ## Design
# Decisions live here, linked as [[token-refresh]].

Step 2

Import once, re-import forever

Import is a pipeline, not a copy. Each file is linted with mordant (fixable formatting healed on the way in), split into semantic chunks by a Rust Markdown parser, embedded with Jina v5 through the embroider ONNX session, and linked — path links and wikilinks resolved against a name index, broken ones tracked for later repair. File hashes are recorded, so the second import of an unchanged folder is nearly free: only changed files re-embed. Nothing here is destructive; the bundle is never modified by importing it.

okf import --all --bundle kb/
# lint → chunk → embed → link → ladybug index
okf import --all --bundle kb/   # second run: deltas only

Step 3

Ask, in three gears

Search fuses dense vectors with full-text matches (RRF), at concept or chunk granularity. When the embedding model isn't loaded — a cold session, a quick check — the PPR gear answers from the link graph alone: lexical seeds expanded by exact Personalized PageRank, in milliseconds. Reading is budget-aware: read returns the concept first, then PPR-ranked neighbours, trimmed to your token budget, so a RAG context window is filled in order of usefulness, not retrieval order.

okf search "how are sessions revoked?"
okf search "sessions" --rank ppr        # cold: no model load
okf read session-auth --include context --max-tokens 1500

Step 4

Grow it while you work

Knowledge work produces knowledge. Instead of letting decisions evaporate at session end, persist reasoning directly: ingest --kind thoughts stores it as a searchable concept under a namespaced ID (thoughts/auth-refactor/…), no file required. PDFs and Office documents ride the same command — bobine converts them to Markdown first, through whichever page route each page earns. Everything ingested is linted, chunked, embedded, and linked exactly like an import, because it goes through the same pipeline rather than a side door.

okf ingest --kind thoughts --thoughts "Chose short-lived refresh…" --topic auth
okf ingest --kind pdf --pdf-file paper.pdf --auto-import

Step 5

Keep it healthy, prove it, share it

Corpora rot: links break, titles duplicate, content goes stale. doctor scores the whole graph 0–100 and repairs what's safe (never touching reviewed: true), while diff shows drift between the graph and the folder — both with CI exit codes, so health becomes a gate rather than a chore. When the knowledge needs to travel, export writes it back out as Markdown — enriched with See Also and Cited By sections from the graph — in OKF format or as an Obsidian vault that re-imports edge-losslessly.

okf doctor --strict      # exit 1 on any finding: gate the PR
okf diff                 # graph vs folder drift
okf export --all --output out/ --flavor obsidian

03 · Core features

Everything a knowledge base needs.
Nothing it doesn't.

The feature set is deliberately closed: each capability below earned its place by serving the loop above, and anything that didn't — dashboards, hosted sync, proprietary formats — was left out. Slim dependencies and no legacy fallbacks are not slogans; they are why installing the graph doesn't install a machine-learning workstation.

Hybrid search

Dense Jina v5 vectors fused with full-text search by RRF — at concept and chunk granularity. Matryoshka truncation (default 512 dims) keeps the index lean without re-embedding, and the model-plus-precision pair is pinned per graph so vector spaces can never silently mix.

Model-free PPR

Lexical seeds → exact Personalized PageRank over the link graph. Topic search with no embedding model loaded — cold sessions answer in milliseconds, and agents get a retrieval gear that works before any download finishes.

Delta-aware import

File hashes decide what changed; only changed files re-embed. --purge drops deleted concepts (with tombstones and soft-delete safety), and multi-root bundles let several folders share one index under @alias/ namespaces.

Doctor & diff

A 0–100 health score (broken links, orphans, stale, duplicates, missing descriptions) with safe --fix; structural diff for drift between graph and folder. Both speak --json and CI exit codes.

Obsidian interop

Wikilinks resolve by uid → aliases → title → stem; ambiguous names never resolve, broken ones are tracked and repairable. Export --flavor obsidian round-trips edge-losslessly — your vault and your graph stay the same corpus.

Image awareness

Caption route for cheap text graphs; ONNX vision route (Jina omni-nano, paired with text-nano) embeds actual image content. Content-hash dedup across the corpus, okf-asset:// links, staged asset store.

Thoughts as knowledge

Persist session reasoning directly — ingest_thoughts(text, topic). Namespaced IDs (thoughts/<topic>/<ts>_<id>) export into a tidy tree. File-free mode runs a whole graph with no bundle directory: thoughts in, search out.

Produce from data

okf produce --from sqlite renders any database as a bundle — one concept per table, FKs as links — with auto-generated ## Observations (empty tables, NULL/dup rates, orphan FKs) and a log.md changelog. Stdlib only, lint pre-flighted, CLI-only by design.

04 · Retrieval

Three gears, one deterministic engine.

Retrieval quality usually comes at the cost of reproducibility: re-rankers sample, tie-breaks wobble, and the fifth run disagrees with the first. OKFgraph refuses the trade. Every query runs the same pipeline in the same order — pure ranking functions over sorted inputs, fixed PPR constants, fixed accumulation order — and golden fixtures pin PPR scores, diff reports, and doctor scores byte-stable across machines. The practical payoff is that knowledge evals mean something: a regression in answer quality shows up as a diff, not a vibe.

The three gears share one index and differ only in how they walk it. The default gear fuses both signals the index holds; the hub gear biases toward authoritative, well-linked concepts; and the PPR gear skips embeddings entirely, which makes it the right choice for cold sessions, topic-map questions, and any environment where the model hasn't downloaded yet.

GearWhenModel loadHow
rank=none defaultOpen questionsOnce per sessionVector + FTS, RRF-fused
rank=hubAuthority mattersOnce per sessionRRF blend with hub (link-authority) scores
rank=pprCold / topic searchNoneLexical seeds → exact Personalized PageRank

Elegant by subtraction

There is no re-ranker service, no sampling temperature, no background thread mutating scores. Chunking is structural (headings and blocks, never mid-sentence slices), pooling is last-token exactly as Jina v5 requires, vectors are L2-normalised Matryoshka truncations. Each of these choices removes a way for two runs to disagree — and what remains is an engine simple enough to hold in your head, and stable enough to build evals on.

okf search "table OCR routing" --rank ppr
# → concepts, no ONNX session, ~ms

okf search "table OCR routing" --target chunks
# → exact passages, expandable to context

okf read slanet --include context --max-tokens 1500
# → self first, then PPR-ranked neighbours

05 · Surfaces

One graph, three doors.

MCP for agents, CLI for humans and CI, Python for pipelines — all three drive the same OKFRouter facade over the same injected components, so behaviour never diverges between surfaces. The tool surface agents see is deliberately the smallest that covers the lifecycle: search, read, traverse, ingest, export. Everything administrative — importing bundles, scoring health, repairing links — stays CLI-only, which keeps prompt context lean and write operations explicit.

06 · Ingestion engine

bobine 0.5.13

Standalone PDF / Office / text → Markdown engine — pure-Rust core, Python bindings. OKFgraph calls it for everything that isn't already Markdown, behind a swappable DocumentConverter seam, which means the converter can evolve (or be replaced) without touching the graph. Its own discipline mirrors the stack's: a single pinned ONNX Runtime, no torch, no optimum, no opencv — not even on the Python side — with GPU behaviour decided by measurement rather than optimism.

The signature idea is routed pages: every page takes exactly the pass it needs. Born-digital text extracts in milliseconds and never sees a model; formula-bearing pages get surgical TexTeller crops; only scans pay for full structure analysis. Office documents take a parallel path — format-sniffed, converted to Markdown, with Excel additionally yielding per-sheet CSV and typed JSON, and embedded pictures staged to content-hash assets.

Routed pages

never for born-digital text (milliseconds), surgical for formulas only, always for full structure on scans. Line-aware math detection merges multi-line display equations while keeping columns apart.

Formula OCR

TexTeller ONNX decodes math regions to LaTeX — int8 default (~319 MB), KV-cached, ~5× faster per crop than the legacy backend it replaced, with preprocessing matched exactly to upstream.

Layout + tables

DocLayout-YOLO structure, PaddleOCR lines in reading order, SLANet-plus table structure — CPU-pinned by measurement, not superstition (see below).

Office, fully

docx/xlsx/pptx plus legacy doc/xls/ppt. Excel yields per-sheet CSV and typed JSON alongside Markdown; embedded pictures stage to content-hash assets.

Measured, not assumed (RTX 3090 · single pinned ORT)

Each row below is a bench, not an estimate — and the routing column is the point: CUDA wins layout and OCR by an order of magnitude, loses tables by up to 6× (SLANet's graph fragments across devices), and quantization helps only where the hardware agrees with it. The defaults encode this ledger, so users get the fast path with zero configuration.

07 · Embedding runtime

embroider 0.3.1

Jina v5 text + image embeddings over ONNX Runtime — Rust core, PyO3. The shared session-policy library both OKFgraph and bobine build on: one pinned runtime, per-slot CPU/CUDA routing, golden-vector conformance. Its defining boundary is ownership — embroider holds sessions and policy, while each consumer process owns inference — which is why two crates can share one ONNX Runtime without sharing failure modes.

The contract it enforces is what keeps every stored vector comparable with every other: a frozen vision resize grid, last-token pooling, L2 normalisation, a fixed Matryoshka ladder, and acquisition that fails closed — a dimension or contract mismatch aborts before a single vector is written, so a mid-run model switch can never silently poison an index. And because precision rules are explicit (fp32 on CPU, fp16 on CUDA, fp16-on-CPU a hard error rather than a stall), performance behaviour is as pinned as numerical behaviour.

One runtime

SessionPolicy::ort_defaults() binds a single onnxruntime==1.29.0 dylib — CPU or CUDA, never both, chosen by install extra, never by luck. An availability probe decides per slot; CPU-only libraries probe false at zero cost.

Devices × precision

cpu XOR cuda; fp32 on CPU, fp16 on CUDA. Per-model provider lists encode what the benches proved, with explicit overrides when you know better.

Frozen contract

Smart-resize vision contract, last-token pooling, L2-norm, Matryoshka ladder. Checked-in golden vectors fail the build on drift — alignment with stored indexes is structural, not hoped-for.

Fail-closed acquisition

Models fetch from pinned revisions into a versioned cache with content-hash filenames. A Meta mismatch aborts before anything is written; concurrent processes share the cache safely.

08 · The stack

Three crates, one philosophy:
slim deps, no legacy fallbacks.

Each layer does exactly one job and trusts its neighbours to do theirs: OKFgraph curates and retrieves, bobine converts, embroider embeds. Shared floors (one ONNX Runtime, one embroider minor range) keep the trio in lockstep without coupling their releases — any 0.3.x embroider serves, any compliant converter can sit behind the seam. The whole install is a handful of pinned packages; what isn't needed isn't installed.
