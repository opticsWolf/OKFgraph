OKFgraph 0.9.0

Knowledge base as a bundle: one Markdown file per concept, frontmatter metadata, [[wikilinks]], content-hash image assets. Import once into SQLite; search with hybrid retrieval (FTS5 + RRF-fused dense vectors + optional PPR/hub expansion). Files stay human-readable forever — the database is a derived index, and okf export round-trips it back.

What it does

  • Ingest anything — Markdown, PDF, Office, thoughts, SQLite databases (okf produce), with mordant lint on the way in.
  • Retrieve — hybrid search tuned for RAG: dense + sparse + graph expansion, deterministic output.
  • Serve agents — exactly 5 MCP tools (ingest, search, read, traverse, doctor), stdio or HTTP.
  • Work file-free — run a whole graph from SQLite alone; thoughts in, search out, no bundle directory required.

Quick start

from okfgraph import OKFRouter
r = OKFRouter(bundle_root="./notes", db_path="graph.db")
r.import_from_okf("./notes")          # index the bundle
hits = r.search_hybrid("how is table OCR routed?", top_k=5)
r.export_db("graph.db", "./out")      # DB back to Markdown

bobine 0.5.13

Standalone PDF / Office / text → Markdown ingestion engine — pure-Rust core, Python bindings. The converter OKFgraph calls for everything that isn't already Markdown.

Pipeline

  • Fast path — pdf_oxide extracts born-digital text in milliseconds; pages route NEVER / AUTO / SURGICAL / ALWAYS.
  • Layout + OCR — DocLayout-YOLO structure, PaddleOCR lines, line-aware reading order.
  • Formulas — TexTeller ONNX (int8 default, ~319 MB) decodes math regions to LaTeX, ~5× faster than the legacy backend.
  • Tables — SLANet-plus structure recognition, CPU-pinned by design.
  • Office — docx/xlsx/pptx + legacy doc/xls/ppt; Excel also exports per-sheet CSV + typed JSON; pictures stage to content-hash assets.

embroider 0.3.1

Jina v5 text + image embeddings over ONNX Runtime (Rust core, PyO3). The shared session-policy library both OKFgraph and bobine build on — one pinned runtime, per-slot CPU/CUDA routing, no torch anywhere.

What it owns

  • Session policy — SessionPolicy::ort_defaults(): one onnxruntime==1.29.0 dylib, EP-availability probe, per-model provider lists.
  • Jina v5 engine — text-small / text-nano (fp32/fp16/int8) + omni-nano vision, frozen contract, golden-vector conformance.
  • Devices & precision — cpu XOR cuda, fp32-CPU / fp16-CUDA (fp16-on-CPU is a hard error, not a stall).
  • Ownership boundary — embroider holds sessions and policy; each consumer process owns inference. bobine uses the policy only.
